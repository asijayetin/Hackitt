# Hackitt backend (simple MVC)

The backend uses Express routes, controllers, Mongoose models and MongoDB Atlas. Passwords are hashed and protected APIs use a JWT token.

## Run on your computer

1. Install Node.js LTS and MongoDB Atlas access.
2. In this `backend` folder, copy `.env.example` to `.env`.
3. Put your Atlas connection string in `MONGO_URI` and a long private value in `JWT_SECRET`.
4. Open a terminal in this folder and run `npm install`, then `npm run dev`.
5. Open `http://localhost:5000/api/health`. You should see `Hackitt API is working`.
6. Open the frontend through VS Code Live Server. The frontend API address is in `js/api.js`.

Never commit `.env` or send its contents in chat. The example file has placeholders only.

## API list

| Method | URL | Access | Body |
| --- | --- | --- | --- |
| GET | `/api/health` | Public | — |
| POST | `/api/auth/signup` | Public | `firstName`, `lastName`, `email`, `password`, `role`, optional `skill` |
| POST | `/api/auth/login` | Public | `email`, `password` |
| GET | `/api/auth/profile` | Own token | — |
| PUT | `/api/auth/profile` | Own token | `firstName`, `lastName`, `email`, optional `skill` |
| DELETE | `/api/auth/profile` | Own token | —; deletes own account and participant records (organizers must delete their hackathons first) |
| GET | `/api/hackathons` | Student or organizer token | — |
| GET | `/api/hackathons/:id` | Student or owning organizer token | — |
| POST | `/api/hackathons` | Organizer token | `name`, `description`, `minTeamSize`, `maxTeamSize`, optional `initialTeamCount`, optional `requiredSkills`, optional `prizePool` (`first`, `second`, `third`) |
| PUT | `/api/hackathons/:id` | Organizer who owns the hackathon | Any editable fields from create; only before students join and while registration is open |
| DELETE | `/api/hackathons/:id` | Organizer who owns the hackathon | —; also removes its teams and related team-change requests |
| POST | `/api/hackathons/:id/join` | Student token | — |
| PATCH | `/api/hackathons/:id/status` | Organizer token | `status`: `open` or `closed` |
| PATCH | `/api/hackathons/:id/results` | Organizer token | `winners`: team IDs in 1st, 2nd, 3rd place order (close registration first) |
| GET | `/api/participants` | Organizer token | — |
| POST | `/api/participants` | Organizer token | Student `firstName`, `lastName`, `email`, `password`, optional `skill` |
| GET | `/api/participants/:id` | Organizer token | — |
| PUT | `/api/participants/:id` | Organizer token | Student profile fields to update |
| DELETE | `/api/participants/:id` | Organizer token | —; deletes the student and associated participation data |
| GET | `/api/teams` | Public | — |
| POST | `/api/teams` | Organizer token | `name`, `maxSize`, optional owned `hackathonId` |
| GET | `/api/teams/:id` | Public | — |
| PUT | `/api/teams/:id` | Organizer token (event owner for event teams) | `name`, `maxSize` |
| DELETE | `/api/teams/:id` | Organizer token (event owner for event teams) | — |
| POST | `/api/teams/generate` | Organizer token | `teamSize` (2–10), `teamCount` (1–20) |
| GET | `/api/teams/pending` | Organizer token | — |
| POST | `/api/teams/:id/join` | Student token | — |
| POST | `/api/team-change-requests` | Student token | `reason` |
| GET | `/api/team-change-requests/mine` | Student token | — |
| GET | `/api/team-change-requests` | Organizer token | — |
| GET | `/api/team-change-requests/:id` | Request owner or organizer token | — |
| PUT/PATCH | `/api/team-change-requests/:id` | Organizer token | `status`: `approved` or `rejected` |
| DELETE | `/api/team-change-requests/:id` | Request owner (pending only) or organizer token | — |

Send the login/signup token in the `Authorization` header as `Bearer <token>`.

For a new event, the organizer creates a hackathon, chooses team sizes, starter team count, and the three prize amounts. The first students each start a team; later students are assigned to teams with room, balancing repeated skills where possible. If all teams are full, a new one is created automatically. Registration can be closed or reopened by the organizer. After closing registration, the organizer selects winning teams; the event and a snapshot of the winning team members are saved as completed history.

## Deploy the backend to Render

The root `render.yaml` describes the backend web service. In Render, create a Blueprint from this repository and provide `MONGO_URI` from MongoDB Atlas. `JWT_SECRET` is generated by Render. The service health check uses `/api/health`.

After deployment, set `API_URL` in `js/api.js` to the Render service URL plus `/api` if the generated service URL differs from the one already configured.
